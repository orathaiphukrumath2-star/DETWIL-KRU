## หัวใจของระบบ

หนึ่งชุดผลงานรวบรวมแผนการจัดการเรียนรู้ สื่อที่ใช้ตามแผน ผลงานผู้เรียน (ถ้ามี) และหลักฐาน/ผลการจัดการเรียนรู้ ใช้ลิงก์ HTTPS หรือไฟล์แนบ แล้วเผยแพร่เป็นหน้าเดียว `/works/<WorkID>`

ยังใช้ Next.js/Vercel + Google Apps Script + Google Sheets + Google Drive เดิม ไม่ได้ย้ายไป Firebase ตามภาพพิมพ์เขียวเก่า และไม่ได้สร้างข้อมูลครู/โรงเรียน/ผลงานสมมติในชีตจริง

## หน้าจอ

- `/studio`: เข้าสู่ระบบ จัดการชุดผลงาน คิวตรวจ โรงเรียนและบัญชีผู้ใช้
- `/works/<WorkID>`: หน้าเผยแพร่สาธารณะ ไม่ต้องเข้าสู่ระบบ
- `/works/<WorkID>?preview=1`: ฉบับบันทึกล่าสุดสำหรับเจ้าของและผู้ตรวจที่มีสิทธิ์ ต้องเข้าสู่ระบบ รวมหลักฐานส่วนตัว
- `/activate?token=...`: ตั้งรหัสผ่านแรกของผู้ดูแลจากลิงก์ใช้ครั้งเดียว อายุ 15 นาที
- หน้าหลักโหลดคลังผลงานจริง ค้นหา/กรอง/แบ่งหน้า และนับการรับรองของรุ่นที่เผยแพร่ ตัวเลขบุคลากรที่ยังไม่เชื่อมยังไม่แสดงเป็นข้อมูลจริง

## โครงสร้างชีต

เพิ่มเพียง `WORKS` และ `AUTH_SESSIONS` จาก 27 เป็น 29 ตาราง โดยคงตารางเดิมทั้งหมด:

- `WORKS`: เจ้าของ โรงเรียน เนื้อหาร่าง รุ่นล่าสุด สถานะตรวจ และสำเนาเนื้อหาที่เผยแพร่
- `AUTH_SESSIONS`: เก็บ hash ของ session token เท่านั้น อายุ 8 ชั่วโมง ไม่เก็บ token จริง
- `RECORD_VERSIONS`: สำเนาแต่ละรุ่นที่บันทึก
- `FILES`: อ้างอิงไฟล์ใน Drive และเจ้าของผลงาน
- `REVIEWS`: ผลตรวจ/ความคิดเห็น พร้อมระดับและ VersionID
- `WORKFLOW_LOG`: ประวัติการบันทึก เผยแพร่ ส่งตรวจ ถอนคำขอ และผลตรวจ
- `SCHOOLS`, `USERS`, `USER_ROLES`, `AUTH_CREDENTIALS`: ใช้ตารางเดิม

ฟังก์ชันอัปเกรดเพิ่มเฉพาะตารางใหม่ หากพบหัวตารางใหม่ไม่ตรงจะหยุด ไม่เขียนทับหัวตารางที่มีข้อมูล ผู้ดูแลยังแก้ข้อมูลอ้างอิงในชีตได้ แต่ไม่ควรแก้ ID, JSON, token hash หรือสถานะอนุมัติด้วยมือ เพราะจะข้ามประวัติและการตรวจสิทธิ์

## การตรวจและเผยแพร่

`DRAFT → SCHOOL_PENDING → SCHOOL_APPROVED → DISTRICT_PENDING → DISTRICT_APPROVED`

ผู้ตรวจส่งกลับแก้ไขหรือไม่รับรองได้ โดยต้องมีความคิดเห็น เจ้าของถอนคำขอได้ ผู้ตรวจโรงเรียนต้องเป็น SCHOOL_ADMIN ของโรงเรียนเดียวกัน ผู้ตรวจเขตใช้ SUPERVISOR/AREA_ADMIN/SUPER_ADMIN ห้ามตรวจผลงานตนเอง

เผยแพร่และส่งตรวจเป็นคนละสถานะ เจ้าของสามารถเผยแพร่ก่อนรับรอง แต่หน้าเว็บระบุว่ายังไม่ได้รับรอง การส่งโรงเรียนตรวจต้องมีแผนและสื่ออย่างน้อยประเภทละหนึ่งรายการ การเผยแพร่ต้องอนุญาตเผยแพร่แผนและสื่ออย่างน้อยประเภทละหนึ่งรายการด้วย

ระหว่างรอตรวจห้ามแก้เนื้อหา ต้องถอนคำขอก่อน การแก้หลังรับรองสร้างรุ่นใหม่และกลับเป็น DRAFT หน้าเผยแพร่เดิมยังคงรุ่นเก่าและผลรับรองของรุ่นเก่า จนกดอัปเดตหน้าเผยแพร่ เมื่ออัปเดตเป็นรุ่นใหม่จะไม่ยืมตรารับรองของรุ่นก่อน

ตั้งแต่รุ่น 0.3 สิทธิ์ยึด `USER_ROLES` พร้อมขอบเขตโรงเรียน ช่วงวันที่ และบทบาทที่สมาชิกเลือกใน session ไม่ใช้ PrimaryRole เป็นสิทธิ์เพียงอย่างเดียว

## ไฟล์และความเป็นส่วนตัว

รองรับ PDF, PNG, JPEG, WebP, DOCX, PPTX ขนาดไม่เกิน 2 MB ต่อไฟล์ สูงสุด 20 หลักฐานต่อชุด ไฟล์ใหญ่ใช้ลิงก์ Google Drive/แหล่งสื่อแทน ขนาดนี้เผื่อการเข้ารหัส base64 ให้อยู่ใต้ [ข้อจำกัด payload ของ Vercel](https://vercel.com/docs/functions/limitations)

ไฟล์อัปโหลดเก็บในโฟลเดอร์ `WorkAttachments` ของ Drive root เดิม ต้องไม่เปิดแชร์สาธารณะ ดาวน์โหลดผ่าน API ที่ตรวจสิทธิ์และรุ่นผลงาน ไม่เปิด Drive ทุกไฟล์เป็น anyone-with-link

หลักฐานผู้เรียนและหลักฐานผลการสอนเริ่มต้นไม่เผยแพร่ เจ้าของต้องเลือกอนุญาตเอง Public API ตัดหลักฐานส่วนตัวออกจาก JSON ด้วย ไม่ใช่ซ่อนเฉพาะปุ่มบนหน้าจอ ส่วนลิงก์ภายนอกใช้สิทธิ์ของเจ้าของลิงก์นั้น ระบบไม่ได้เปลี่ยนการแชร์ Google Drive ภายนอกอัตโนมัติ ไฟล์อัปโหลดไม่ได้ผ่านระบบสแกนไวรัส

รหัสผ่านเก็บ hash/salt ตาม AuthService เดิม ไม่เก็บ plaintext; session cookie เป็น HttpOnly, SameSite=Lax และ Secure บน production; API เขียนข้อมูลตรวจ Origin; หน้าเปิดใช้งานตั้ง Referrer-Policy=no-referrer ไม่เปิด HtmlService/google.script.run เพื่อหลีกเลี่ยงการเรียก repository helpers โดยตรง

- Apps Script production health ผ่าน version 0.2.0, schemaOk=true; publicWorks ตอบรายการว่างจริง (0 รายการ)
- ยังไม่ได้ทดลองบันทึก/อัปโหลด/อนุมัติจริงบนชีต Google เพราะต้องให้เจ้าของเปิดใช้รหัสผ่านผู้ดูแลก่อน
